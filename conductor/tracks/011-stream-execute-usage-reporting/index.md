**Type**: dev
**Summary**: `streamExecute()` (both `index.js`'s top-level class and `lib/engine/index.js`'s engine) is a plain generator pass-through — unlike `execute()`, it never persists to `usage_data`/`prompt_variables` once the stream completes, and never checks/writes the cache either. Originally found and scoped from the coachai side (Track 067 there) while debugging prompt-construction issues in `ai-chat.mjs`'s streaming chat path — a query for `full_prompt` on `endpoint = 'chat_stream'` came back empty despite ~1470 rows existing for every non-streaming endpoint. Moved here since the fix is entirely inside this package, not coachai. Re-verified live during Track 010's work: a real streamed Vertex call's **last** chunk carries full `usageMetadata` (`promptTokenCount`/`candidatesTokenCount`/`totalTokenCount`, plus a `thoughtsTokenCount` for "thinking" models) — earlier chunks carry none — confirming the reporting step needs to accumulate content across all chunks but only has real usage numbers once the stream is exhausted. This gap is exactly what's currently limiting visibility into Track 010's remaining, only-partially-explained latency regression (coachai's real streaming chat path has zero queryable prompt/latency/token history today).
