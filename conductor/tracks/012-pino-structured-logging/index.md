**Type**: dev
**Summary**: Discovered while investigating Track 011's own persist-failure catch block: a real ~76s streamed call completed successfully but left no `usage_data` row, and the `console.warn` meant to surface that failure was unrecoverable — consumers that pipe stdout straight into a structured-log viewer (`node server/index.mjs | npx pinorama --open`, coachai's own dev setup) silently drop plain-text lines, since pinorama expects newline-delimited pino JSON. TokenTalos has zero `pino` dependency today — all 17 real diagnostic call sites across `lib/engine/*.js` and `index.js` are plain `console.log`/`warn`/`error`. Fix: add `pino`, create a small shared logger (`lib/logger.js`) with a lazily-created default instance, let `TokenTalosEngine`/`LLMGateway`/`TokenTalos` accept an optional `config.logger` override (so a consumer like coachai can inject its own pino instance and see tokentalos's logs unified in the same stream), and convert all 17 call sites. Once this ships, piping through pinorama (or any pino-aware viewer) will actually surface tokentalos's own diagnostics instead of dropping them. Scoped to `lib/engine/*.js` + `index.js` only — `bin/tokentalos.js`'s CLI output and `api/*.js`'s dashboard/collector server are explicitly out of scope (console output IS the CLI's UI; the API server is a separate concern).
