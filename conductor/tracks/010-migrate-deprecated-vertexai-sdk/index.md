# Track 010: Migrate off deprecated @google-cloud/vertexai SDK

**Lane**: implement
**Lane Status**: running
**Progress**: 75%
**Phase**: Vertex path migrated (Phases 1-3, 5 done) and verified end-to-end from coachai via a local symlink. Confirmed a real, substantial fix (15-28s -> 8.5-9.7s for the reproduction case) but only PARTIAL recovery vs. the ~1.2s historical baseline — a separate coachai-side performance investigation is warranted for the remainder. Remaining: Phase 4 (Gemini-direct path, lower priority) and Phase 6 (publish + switch coachai off the symlink).
**Type**: dev
**Summary**: Discovered from coachai (a TokenTalos consumer) reporting severe, sudden chat-response slowness. Investigation (in coachai's own conductor/tracks, cross-referenced here) ruled out every app-level and recent-commit hypothesis by directly reproducing the slowdown with a bare script that bypasses the consumer app entirely — replaying identical prompt content that took ~1.2s on 2026-07-13 now takes 5-9+ seconds when replayed today (2026-07-19) through this exact TokenTalos package, with nothing else different. Every real run also prints: "The VertexAI class and all its dependencies are deprecated as of June 24, 2025 and will be removed on June 24, 2026" — we are now roughly a month past that removal date. `lib/engine/llm_clients.js` constructs `new VertexAI(pgConfig)` from `@google-cloud/vertexai` (`getVertex()`) and calls `.getGenerativeModel({model}).generateContent(...)`/`.generateContentStream(...)` (`executeVertex()`/`streamExecuteVertex()`) — this is the exact code path coachai's production traffic goes through (`useVertex: true`, no `GEMINI_API_KEY` configured, so Vertex is always preferred per `executeGemini()`'s own fallback logic). Fix: migrate this path to the new unified `@google/genai` SDK, which Google's own deprecation notice recommends and which is confirmed (via Google's migration guide) to support the same Vertex AI (project/location) configuration model.
