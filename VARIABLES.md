# TokenTalos Special Variables

To enable advanced tracking, safety, and reasoning features, TokenTalos recognises specific variable names. Using these names in your prompt parts triggers specialised engine behavior.

## Core Reserved Variables

| Variable Name | Purpose | Engine Behavior |
| :--- | :--- | :--- |
| `system` | Standard instructions | Mapped to LLM 'system' role. High-priority tracking. |
| `user_query` | The primary user request | Mapped to LLM 'user' role. Subject to 'Neutralization' (XML wrapping). |
| `history` | Chat history messages | Mapped to 'user'/'assistant' roles. Subject to 'Neutralization'. |
| `context` | RAG or background data | Analyzed for 'Context Bloat' in Engine Insights. |

## Intelligence & Safety Variables

Using these names enables advanced analysis in the TokenTalos Dashboard.

### `safety_guardrails`
*   **Purpose:** Static rules about what the AI should and should not do (e.g., "No medical advice").
*   **Behavior:** When you perform an **OPV (Reasoning Verification)** check, this content is automatically injected into the verifier as the "Ground Truth" constraints to check against.

### `thinking` / `reasoning`
*   **Purpose:** The internal chain-of-thought or reasoning tokens generated by the model.
*   **Behavior:** The Dashboard prioritises these variables for **OPV analysis**. It allows the verifier to "read the AI's mind" to ensure it's following the logic correctly before it produces a final answer.

## Custom Variables
You can use any arbitrary name (e.g., `past_pages`, `character_state`). TokenTalos will track their token counts and cost attribution separately, providing you with a "Token Heatmap" of your prompt's architecture.
